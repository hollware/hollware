# Threat model

What v1.0 has to answer for, checked against the code and the tests as of 2026-10-16 (`main` at `88072f7`). Each threat has one row. `guard` names the test file and the test title, as it appears in `it(...)`, that fails when the mitigation goes; a `%s` or `$name` title is an `it.each`. Statuses:

- `guarded`: a test or a check holds the mitigation, and it would fail if the mitigation were removed.
- `partial`: some of it is held; the note says what is not.
- `gap`: nothing holds it, or the mitigation is missing.
- `accepted`: a risk the design takes on purpose, with the ADR or the reason.

Paths are relative to the repository root. `server/` stands for `packages/server/`, `core/` for `packages/core/`.

## Open, by priority

Every gap of the first reading (2026-10-16) is closed or accepted; what is left is partial, highest risk first.

1. **T-34, refresh token replay** (partial). The OAuth library keeps the previous refresh token valid until the new one is used, and detects no reuse. Options: wait for the library, wrap its refresh grant to revoke the grant on a reuse, or accept it in an ADR with the access token's lifetime as the bound.
2. **T-101, refusals with no site** (partial). A refusal before the site is known (no token, a wrong one) is in Workers Logs, not in a site's activity log, and a line can be lost if D1 fails after its change.
3. **T-60, images of a previewed draft** (partial). The sandboxed preview still loads a draft's images, which tells their hosts that someone previewed it.
4. **T-91, what no token of a run can read** (partial). The maintainer's 2FA and the npm trusted publisher.

## Out of scope for an internal review

- A DAST baseline (OWASP ZAP or similar) against staging: headers, cookies, redirects, the consent and sign-in pages as a browser sees them.
- An external review of the OAuth flow end to end with real clients (claude.ai connectors, a CIMD client on another domain), including refresh rotation and revocation, against the MCP authorization specification.
- A review of `@cloudflare/workers-oauth-provider` 1.2.3 and `@simplewebauthn/server` 14.0.3 as used, since several mitigations above are their defaults.
- Fuzzing of the Markdown pipeline and the HTML renderer beyond `core/tests/markdown/fuzz.test.ts`, by someone outside the project, with browser-level XSS checks of the rendered output.
- Whether IndexNow and the search engines fetch the key file at the submitted host (T-69), confirmed against the live service.
- Cloudflare account settings: WAF and rate limiting rules, Workers Logs retention (T-55), D1 Time Travel retention, who holds the account and the API tokens and with which permissions.
- GitHub organization settings: rulesets, environment protection, 2FA enforcement, who can push to `release`.
- Load and cost tests against the Free plan limits (requests, CPU, D1 and KV writes) as a denial of service.
- A review of `packages/cli` and `create-hollware` on the user's machine (where tokens and secrets are written, file permissions), which this inventory does not cover.
